From RSS to AI answer — the full pipeline.

1

Fetch — async HTTP

All active feeds are fetched concurrently using httpx.AsyncClient and asyncio.gather(). 50 feeds take the same time as 1. New articles are saved to SQLite; duplicates are ignored by GUID.

2

Sentiment — VADER scoring

Each article's title + description is scored using VADER — a rule-based model optimized for short social/news text. Returns a compound score from −1.0 (very negative) to +1.0 (very positive). No API, runs locally in milliseconds.

3

Embed — semantic vectors

The text of each article is converted to a 384-dimensional vector by all-MiniLM-L6-v2 (sentence-transformers). These vectors capture meaning, not just words — so "AI funding round" and "startup raises capital for machine learning" land close together in vector space. Stored in ChromaDB.

4

Summarize — Claude agent

Each new article is sent to Claude with a system prompt: "Summarize in 1–2 sentences." The result is stored back in SQLite. Batched, async, gracefully skipped if no API key is set.

5

Q&A agent — tool use

When you ask a question, Claude doesn't see all articles at once. Instead it receives a list of tools (semantic_search, get_recent_articles, get_feed_stats) and decides which ones to call. It runs multiple tool calls, receives results, and synthesizes a final answer with cited sources.

Theory explained simply

What's actually happening inside.

Three concepts power feedwatch. Here's what they mean in plain English — and what the code actually does.

🧮 Vector embeddings

An embedding is a list of numbers that represents the meaning of a text. Similar texts produce similar numbers. The model learned this from billions of sentences.

feedwatch converts every article to a 384-number vector and stores it in ChromaDB. When you search, your query is also converted to a vector — and we find the closest articles using cosine distance.

# "Python performance" becomes: [0.12, -0.34, 0.87, 0.02, ...] # 384 numbers # "fast Python code" → similar vector [0.11, -0.31, 0.89, 0.04, ...] # close = relevant # distance between them: 0.03 → TOP RESULT

😊 Sentiment analysis

VADER (Valence Aware Dictionary and sEntiment Reasoner) uses a hand-crafted dictionary of words with emotional scores, plus rules for negation, punctuation, and capitalization.

It returns a compound score: positive words push it up, negative pull it down. Fast, offline, no model download needed.

# "Amazing breakthrough in AI!" compound = +0.82 → positive # "Critical security flaw found" compound = -0.61 → negative # "Meeting scheduled for Tuesday" compound = +0.04 → neutral

🤖 AI agent with tool use

Tool use (function calling) lets Claude decide what to do instead of just generating text. You define tools as JSON schemas; Claude picks which ones to call and with what arguments.

feedwatch's Q&A agent has 4 tools. Claude reasons about which ones it needs, calls them against your local database, and builds the answer from real data.

# You ask: "Any positive AI news?" # Claude calls: semantic_search("AI news", n=8) get_articles_by_sentiment("positive") # Gets results → writes answer # with cited article URLs

⚡ Async Python

asyncio lets one thread handle many tasks at once by switching between them while waiting for I/O (network, disk). Perfect for fetching many feeds simultaneously.

feedwatch uses asyncio.gather() to fetch all feeds in parallel — 50 feeds in the time of 1. The FastAPI server and SQLAlchemy database are also fully async.

# Sequential (slow): for feed in feeds: await fetch(feed) # 50 × 1s = 50s # Async parallel (fast): await asyncio.gather( *[fetch(f) for f in feeds] ) # all at once = ~1s

🗄️ ORM — object-relational mapping

SQLAlchemy ORM maps Python classes to database tables. You work with Article objects instead of writing raw SQL. Relationships, queries, and migrations all in Python.

# Instead of raw SQL: # SELECT * FROM articles WHERE ... # You write Python: result = await db.execute( select(Article) .where(Article.sentiment_label == "positive") .order_by(Article.fetched_at) )

🏗️ REST API

REST (Representational State Transfer) is a convention for web APIs: use HTTP verbs (GET, POST, DELETE) on resource URLs. FastAPI generates OpenAPI docs automatically from Python type hints.

# GET /feeds/ → list feeds # POST /feeds/ → add feed # DELETE /feeds/1 → remove feed # GET /articles/ → list articles # POST /refresh → run pipeline # POST /ask → AI agent

Get started

Up and running in 3 minutes.

Requires Python 3.11+ and uv — the fast Python package manager.

bash
# 1. clone git clone https://github.com/navidofek-cmyk/feedwatch cd feedwatch # 2. install everything (creates .venv automatically) uv sync # 3. configure — add your Anthropic API key cp .env.example .env # 4. add your first feed uv run feedwatch add https://hnrss.org/frontpage --name "Hacker News" uv run feedwatch add https://feeds.arstechnica.com/arstechnica/index --name "Ars Technica" # 5. fetch, analyze, embed, summarize uv run feedwatch refresh # 6. ask uv run feedwatch ask "What happened in AI today?" # 7. open the web UI uv run feedwatch serve # → http://localhost:8000

The ANTHROPIC_API_KEY in .env is only needed for AI summaries and the Q&A agent. All other features (fetching, sentiment, semantic search, web UI) work without it.

CLI reference

All commands.

Run feedwatch --help or feedwatch <command> --help for full options.

feedwatch add <url> --name "Name"
Add a new RSS feed to the database.
feedwatch remove <id>
Remove a feed and all its articles.
feedwatch feeds
List all feeds with article counts.
feedwatch refresh
Full pipeline: fetch → analyze → embed → summarize.
feedwatch list --hours 6 --sentiment positive
Browse articles with filters.
feedwatch top --hours 24 --num 5
Top positive and negative articles.
feedwatch search "query"
Semantic vector search over articles.
feedwatch ask "question"
Ask the Claude AI agent about your feeds.
feedwatch demo
Run interactive demo. No API key or network needed.
feedwatch serve
Start web UI + REST API at localhost:8000.
